Como testar o SMAUG no Swagger

Passo a passo para abrir a documentação interativa, fazer login, autorizar o token JWT e testar as rotas da API sem Postman.

Endereço local: http://localhost:3000/api-docs
Projeto: SMAUG · Express + JWT + Prisma

Para quem é este guia: aluno que nunca usou Swagger. Você vai clicar, colar JSON e ver a resposta da API na própria página.

1. O que é o Swagger?

O Swagger UI é uma página web gerada a partir da especificação OpenAPI. Em vez de digitar comandos no terminal ou montar requests no Postman, você:

  • vê todas as rotas organizadas por tags (Auth, Games, Quiz…);
  • preenche o body de exemplo;
  • clica em Execute;
  • lê o status HTTP e o JSON de resposta.
No SMAUG: a documentação fica em http://localhost:3000/api-docs. O arquivo técnico da API está em backend/src/docs/openapi.json.

2. Antes de começar

1 PostgreSQL ligado, com o banco smaug.

2 Backend rodando:

cd backend
npm run dev
# deve aparecer: Server running on port 3000

3 (Opcional) Frontend na 5173 — não é necessário para testar no Swagger.

Atenção: se a porta 3000 não estiver no ar, a página do Swagger não abre. Suba o backend primeiro.

3. Abrir a documentação

  1. Abra o navegador (Chrome, Edge…).
  2. Digite: http://localhost:3000/api-docs
  3. Você deve ver o título SMAUG API e uma lista de grupos (tags).

Também existe o JSON cru em http://localhost:3000/api-docs.json (útil se alguém perguntar “onde está o OpenAPI?”).

4. Entender a tela

ElementoO que significa
Tags (Auth, Consoles…) Grupos de endpoints. Clique para expandir.
Cores GET / POST / PUT / DELETE Método HTTP da rota.
Cadeado 🔒 Rota protegida: precisa de JWT.
Authorize (botão no topo) Lugar para colar o token depois do login.
Try it out Libera os campos para você editar e executar.
Execute Envia a request de verdade para o backend.
Responses Mostra o código (200, 401…) e o JSON devolvido.

5. Roteiro completo de teste (do zero)

Siga nesta ordem. É o mesmo fluxo que a apresentação pode demonstrar.

Passo A — Registrar um usuário

  1. Abra a tag Auth.
  2. Clique em POST /api/auth/register.
  3. Clique em Try it out.
  4. No body, use um email novo, por exemplo:
{
  "name": "Demo SMAUG",
  "email": "demo@smaug.com",
  "password": "senha123"
}
  1. Clique em Execute.
  2. Espere 201. Na resposta aparece um campo token.
Copie o token agora. Ele é a “pulseira” de acesso. Se o email já existir, use login (Passo B) em vez de register.

Passo B — (Alternativa) Login

  1. Abra POST /api/auth/login → Try it out.
  2. Body:
{
  "email": "demo@smaug.com",
  "password": "senha123"
}
  1. Execute → copie o token da resposta 200.

Passo C — Autorizar o Swagger (muito importante)

  1. No topo da página, clique no botão verde/escuro Authorize.
  2. No campo Value, cole somente o token (sem escrever a palavra Bearer — o Swagger já coloca).
  3. Clique em Authorize, depois Close.
Como saber se deu certo? Os cadeados das rotas protegidas ficam “fechados/autorizados”. Se você esquecer este passo, quase tudo responde 401.

Passo D — Confirmar quem sou eu

  1. Em Auth, abra GET /api/auth/me.
  2. Try it out → Execute.
  3. Deve voltar 200 com name/email (sem a senha).

Passo E — Criar um console

  1. Tag Consoles → POST /api/consoles.
  2. Try it out e use um body assim:
{
  "name": "PlayStation 2",
  "releaseDate": "2000-03-04",
  "manufacturer": "Sony",
  "generation": 6,
  "mediaType": "DVD",
  "images": [],
  "pricePaid": 350,
  "estimatedValue": 500,
  "rating": 9,
  "trivia": "Console mais vendido"
}
  1. Execute → espere 201.
  2. Olhe se veio unlockedAchievements (ex.: primeiro console).
  3. Copie o id do console se quiser testar GET/PUT depois.

Passo F — Criar um jogo

  1. Tag Games → POST /api/games.
  2. Body de exemplo:
{
  "name": "Shadow of the Colossus",
  "releaseDate": "2005-10-18",
  "developer": "Team Ico",
  "saga": "Colossus",
  "genres": ["Action", "Adventure"],
  "consoleName": "PlayStation 2",
  "synopsis": "Wander enfrenta colossos.",
  "trivia": null,
  "coverUrl": null,
  "isDigital": false,
  "pricePaid": 120,
  "estimatedValue": 250,
  "rating": 10
}
  1. Execute → 201.
  2. Se marcar "isDigital": true, o jogo fica marcado como versão digital.

Passo G — Listar e filtrar

  • GET /api/consoles — lista tudo.
  • GET /api/consoles?manufacturer=Sony — filtro.
  • GET /api/games — lista jogos.
  • GET /api/dashboard/stats — totais e gráficos (dados brutos).

Passo H — Busca externa (autocomplete)

  1. Tag External → GET /api/external/games/search.
  2. Em query, digite zelda.
  3. Execute → deve trazer clássicos do catálogo local (e/ou RAWG/Steam).
  4. Pegue um rawgId (ex.: local-zelda-oot) e teste GET /api/external/games/{id}.

Passo I — Quiz

  1. GET /api/quiz/today — vê as 5 perguntas (sem gabarito).
  2. POST /api/quiz/submit com:
{
  "answers": [0, 1, 2, 1, 0]
}

Cada número é o índice da opção (0 = primeira, 1 = segunda…). Ajuste conforme as perguntas que vieram no GET.

  1. Para demonstrar outra geração: POST /api/quiz/reset.

Passo J — Conquistas (demo)

  • GET /api/achievements — vê locked/unlocked.
  • POST /api/achievements/grant com {"code":"QUIZ_MASTER"}.
  • DELETE /api/achievements/unlocked — limpa tudo (útil na demo).

6. O que fazer se der erro

Código / sintomaCausa comumComo corrigir
Página não abre Backend parado cd backend && npm run dev
401 Sem Authorize, ou token errado/expirado Faça login de novo e cole o token no Authorize
400 JSON incompleto ou inválido Compare com o exemplo do schema no Swagger
409 no register Email já existe Use login ou mude o email
404 id inexistente ou de outro usuário Liste primeiro e copie um id válido
500 Banco fora / migration faltando Cheque PostgreSQL e npx prisma migrate deploy
Erro clássico de iniciante: colar Bearer eyJhbGci... no Authorize. Cole só o eyJhbGci.... O Swagger adiciona o Bearer sozinho.

7. Checklist para a apresentação

  1. ☐ Backend no ar → abrir /api-docs
  2. ☐ Register ou Login → copiar token
  3. ☐ Authorize
  4. ☐ GET /me (prova que o JWT funciona)
  5. ☐ POST console + POST jogo
  6. ☐ GET dashboard/stats
  7. ☐ GET external search com “zelda”
  8. ☐ Quiz today → submit ou reset
  9. ☐ Explicar 401 sem token vs 200 com token
Frase pronta: “O Swagger é a documentação interativa da API. Eu autentico com JWT pelo botão Authorize e executo as rotas direto no navegador, sem precisar do frontend.”
